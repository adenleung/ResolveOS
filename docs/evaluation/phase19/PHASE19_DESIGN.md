# Phase 19 pre-implementation design

The pilot is a development benchmark, not a held-out or production reliability claim. A/B/C remain untouched historical fixtures. No paid execution is authorized for implementation.

Audit: reuse EventIngestionService, ExceptionDetectionService, ClassificationService, OrchestrationService, native InvestigationRunner/SupervisorRunner, role tools and strict typed predicate validation. Reuse app.evaluation.disposable_database/case_records and the existing live runner's guarded read-only claims, bank snapshots, safe error codes and per-case metering. Existing migrations and schema suffice; no application migration, worker replacement, frontend, authorization or execution changes are needed. Existing rules-only operational benchmark has modelled labour assumptions; these will not be treated as observations in this benchmark.

Separate runtime, source catalog, scorer and source-only offline providers. Never give providers a catalog, expected answer, case rubric, scenario name or desired completion status. Ground truth is a runner/scorer artifact only. Persist initial sources and pre-registered expert judgements before ingestion, then bind generated event IDs and freeze final source observations before the first provider turn. Later evidence is declared in advance and ingested after native routing. Recheck all frozen hashes at scoring; failures retain partial records and a nonzero exit.

Ten cases: delayed acknowledgement; missing authoritative receipt; payment/ledger disagreement; duplicate logical event with cross-entity idempotency risk; timeout/accepted/completed retry with receipt; incompatible payment/confirmation records; API-only degradation; delayed corrected ledger observation; missing confirmation above an installed policy limit; stale workflow superseded before detection. Distinct source facts and branches, not identifier substitutions of A/B/C. Several development families overlap historical work; no independence/generalization claim.

Substitutions: delayed reconciliation uses a late corrected ledger observation because WORKFLOW is routed but no native investigator handler exists; do not fabricate one. Policy restriction uses a valid existing ControlPolicy in the disposable database plus a missing confirmation and observed rejected-approval state. Policy lookup is read-only; no control authorization is created. Risk policy-applicability mapping is unavailable, and will not be invented. Duplicate-risk sources use the existing shared-idempotency priority rule; cross-entity evidence is not granted to an investigator merely for benchmarking.

Rules baseline uses the identical initial source bytes and native ingestion/detection/classification/routing stages, in a separately owned database. It stops before investigator execution. Advisory synthesis and Supervisor reasoning are CAPABILITY NOT AVAILABLE IN BASELINE. Observe human triage genuinely generated by native rules; do not pretend paused investigator tasks are resolutions or incorrect rule predictions. Compare detection/classification/routing on matched capabilities. Additional AI evidence synthesis is measured separately with explicit limits.

Offline providers derive atomic observations and conservative fixture branches from returned tools only; they are labelled deterministic integration fixtures, not independent reasoning judges. Live mode uses the existing OpenAIProvider, with one per-case budget and a separate shared aggregate reservation envelope. Live CLI requires explicitly selected case IDs, approved paid case count and batch token/request/USD caps; offline is the default. Unknown usage remains reserved and stops the batch, with no retry/fallback. Existing ten-request/120000-token/USD0.15 per-case limits and three turns/twelve tools/2048 output-token caps remain.

Use immutable versioned file exports, not an analytics database. Each case exports source/ground-truth hashes, native task/model/tool records, independently rechecked source predicates, raw decisions, manual review rubric, stage durations and observed/estimated usage. Aggregate precision/recall and other metrics retain numerator, denominator and NOT APPLICABLE for zero populations. Critical safety/integrity/isolation failures fail acceptance regardless of other scores. Human routing before Supervisor differs from an advisory Supervisor escalation after legitimate specialist completion.

Free-text causality, narrative chronology and recommendation quality stay PENDING REVIEW. Pre-register expert materiality and ambiguity; borderline gaps stay PENDING REVIEW rather than automatic accusations of unnecessary escalation. A structured reviewer verdict can finalize subjective categories in a new scoring artifact; prior results remain unchanged. No ROI, employee timing, model accuracy or live Supervisor-quality claim from deterministic fixtures.

Expansion is manifest-driven with family-level development/held-out partitions. Prepare an unrun expansion plan with new family specifications; do not relabel generated ID permutations as independent cases or run paid batches. If held-out outcomes are used for tuning, retire that version to development. Packaging includes all original source and reviewed additions, verifies CRC/SHA256 and all 54 frozen frontend files, preserving earlier archives.
